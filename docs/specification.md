# POLARIS — 詳細仕様書

本文書は、3D Web アプリケーション「POLARIS — 天の北極から見る地球の自転」（パッケージ名：`earth-rotation-viewer`）における天文座標系、天文計算モデル、表示・操作仕様、および実装・テスト方針を定義する。

---

## 1. 天文座標系の定義

### 1.1 3D 空間座標軸（右手座標系）

本アプリでは Three.js 標準の右手座標系を採用し、天球上の基準方向および地球固定座標の基準を以下のように割り当てる。

| 軸 | 地球固定基準（初期回転 $0$ 時） | 天球慣性基準（`sidereal` 時） | 空間内の幾何学的方向 |
|---|---|---|---|
| `+X` | 本初子午線（経度 $\lambda = 0^\circ$） | 春分点（`♈`、赤経 $\alpha = 0^\circ$） | 基準経線方向（水平右） |
| `+Y` | 北極点（北緯 $\phi = +90^\circ$） | 天の北極（赤緯 $\delta = +90^\circ$） | 自転軸の北向き延長方向（上） |
| `-Z` | 東経 $90^\circ$（$\lambda = +90^\circ$） | 赤経 $90^\circ$（$6\text{h}$） | 水平奥方向 |
| `+Z` | 西経 $90^\circ$（$\lambda = -90^\circ$） | 赤経 $270^\circ$（$18\text{h}$） | 水平手前方向 |

球面上の任意の点（半径 $R$、緯度または赤緯 $\phi$、経度または赤経 $\lambda$、いずれも東・北を正）から直交座標 $(x, y, z)$ への変換式は以下となる。

$$x = R \cos\phi \cos\lambda$$

$$y = R \sin\phi$$

$$z = -R \cos\phi \sin\lambda$$

- $R$：地球半径または天球半径（単位球計算時は $R = 1$）
- $\phi$：緯度または赤緯（ラジアン、$-\pi/2 \le \phi \le \pi/2$）
- $\lambda$：東経を正とする経度、または赤経（ラジアン）

### 1.2 天の北極から見て反時計回りになる理由

右手座標系では基本ベクトルの外積が $\vec{e}_x \times \vec{e}_y = +\vec{e}_z$ を満たすため、右手の親指を `+Y` 軸（天の北極の向き）に合わせると、他の4本の指は `+Z → +X → -Z → -X` の順に巻く。上記変換式では経度 $\lambda$ が $0^\circ \to +90^\circ$（西から東）へ増えるにつれて座標が `(+R, 0, 0)`（`+X`）から `(0, 0, -R)`（`-Z`）へ移るため、経度増加方向（地球の自転方向である西から東）は `+Y` 軸正方向周りの正の回転角に一致する。

したがって、`+Y` 軸の遠方（天の北極側）から地球を見下ろすと、地球の自転方向は常に**反時計回り**となる。Three.js で地球オブジェクトに Y 軸周りの回転角 `rotation.y = +θ` を適用した場合、変換行列は次式で作用する。

$$x' = x \cos\theta + z \sin\theta = R \cos\phi \cos(\lambda + \theta)$$

$$y' = y = R \sin\phi$$

$$z' = -x \sin\theta + z \cos\theta = -R \cos\phi \sin(\lambda + \theta)$$

- $\theta$：Y 軸正方向の回転角（`sidereal` フレームではグリニッジ平均恒星時 $\text{GMST}$、`solar` フレームでは $\text{GMST} - \alpha_\odot$）

これにより、回転角 $\theta = \text{GMST}$ を与えるだけで、地球上の経度 $\lambda$ の地点が天球座標上の赤経 $\alpha = \text{GMST} + \lambda$（地方恒星時 $\text{LST}$）へそのまま一致する。

## 2. 天文計算モデル

天文計算モジュールは純粋関数として実装し、任意の協定世界時（UTC）の `Date`（または UNIX ミリ秒 `timestampMs`）から [src/types/astronomy.ts](../src/types/astronomy.ts) で定義された `SolarSystemState` および `CityObservation` を算出する。

### 2.1 ユリウス日（`julianDay`）

UNIX エポック（1970-01-01T00:00:00.000Z）のユリウス日 $\text{JD}_{1970} = 2440587.5$ を基準とし、UNIX ミリ秒 `timestampMs`（1日 $= 86{,}400{,}000\text{ ms}$）から連続ユリウス日 $\text{JD}$ を求める。

$$\text{JD} = \frac{\text{timestampMs}}{86{,}400{,}000} + 2440587.5$$

さらに J2000.0 元期（2000-01-01T12:00:00Z、$\text{JD}_0 = 2451545.0$）からの経過日数 $D$ およびユリウス世紀数 $T$ を定義する。

$$D = \text{JD} - 2451545.0$$

$$T = \frac{D}{36525}$$

- $\text{JD}$：ユリウス日（`julianDay`）
- $D$：J2000.0 からの経過日数（日）
- $T$：J2000.0 からの経過ユリウス世紀数

### 2.2 グリニッジ平均恒星時（`gmstRad`）

春分点に対する本初子午線の回転角であるグリニッジ平均恒星時（以下 GMST）を、度単位の標準多項式で算出する。

$$\text{GMST}_{\deg} = 280.46061837 + 360.98564736629 \cdot D + 0.000387933 \cdot T^2 - \frac{T^3}{38{,}710{,}000}$$

算出した $\text{GMST}_{\deg}$ を $[0^\circ, 360^\circ)$ に正規化したうえでラジアンへ変換し、`gmstRad` $\in [0, 2\pi)$ を得る。

- 1太陽日（$D$ が $+1.0$ 増加）あたり、$\text{GMST}_{\deg}$ は約 $360.985647^\circ$ 進む
- $\text{GMST}_{\deg}$ がちょうど $360^\circ$ 進む所要時間が 1 恒星日（約 $0.99726957\text{ 日}$）となる

### 2.3 太陽の視黄経・赤経・赤緯

J2000.0 からの経過日数 $D$ を用いて、天文年鑑（Astronomical Almanac）の低精度太陽位置計算式（1950〜2050 年頃で精度約 $0.01^\circ$）により太陽の視黄経・赤経・赤緯を算出する。

$$L = (280.460 + 0.9856474 \cdot D) \bmod 360$$

$$g = (357.528 + 0.9856003 \cdot D) \bmod 360$$

$$\lambda_\odot = (L + 1.915 \sin g + 0.020 \sin 2g) \bmod 360$$

$$\varepsilon = 23.439 - 0.0000004 \cdot D$$

- $L$：太陽の平均黄経（度、$[0^\circ, 360^\circ)$ に正規化）
- $g$：太陽の平均近点角（度、三角関数へはラジアン変換して入力）
- $\lambda_\odot$：太陽視黄経（`sunEclipticLongitudeDeg`、度、$[0^\circ, 360^\circ)$）
- $\varepsilon$：黄道傾斜角（度、J2000.0 付近で約 $23.44^\circ$）

太陽視黄経 $\lambda_\odot$ と黄道傾斜角 $\varepsilon$ をラジアンに変換し、赤道座標上の太陽赤経 $\alpha_\odot$（`sunRightAscensionRad`）および太陽赤緯 $\delta_\odot$（`sunDeclinationRad`）を算出する。

$$\alpha_\odot = \operatorname{atan2}(\cos\varepsilon \sin\lambda_\odot,\; \cos\lambda_\odot) \bmod 2\pi$$

$$\delta_\odot = \arcsin(\sin\varepsilon \sin\lambda_\odot)$$

- $\alpha_\odot$：太陽の赤経（ラジアン、$[0, 2\pi)$）
- $\delta_\odot$：太陽の赤緯（ラジアン、夏至付近で約 $+23.44^\circ$、冬至付近で約 $-23.44^\circ$）

| 季節 | 太陽視黄経 $\lambda_\odot$ | 太陽赤経 $\alpha_\odot$ | 太陽赤緯 $\delta_\odot$ | 北半球の日照傾向 |
|---|---|---|---|---|
| 春分 | $0^\circ$ | $0^\circ$（$0\text{h}$） | $0^\circ$ | 全世界で昼夜がほぼ12時間ずつ |
| 夏至 | $90^\circ$ | $90^\circ$（$6\text{h}$） | 約 $+23.44^\circ$ | 北極圏（$66.6^\circ\text{N}$ 以北）が白夜 |
| 秋分 | $180^\circ$ | $180^\circ$（$12\text{h}$） | $0^\circ$ | 全世界で昼夜がほぼ12時間ずつ |
| 冬至 | $270^\circ$ | $270^\circ$（$18\text{h}$） | 約 $-23.44^\circ$ | 北極圏（$66.6^\circ\text{N}$ 以北）が極夜 |

### 2.4 太陽直下点と北極点の昼夜状態

太陽直下点（地表で太陽が天頂に位置する地点）の緯度 `subsolarLatDeg` および経度 `subsolarLonDeg` は次式で求める。

$$\phi_{\text{sub}} = \operatorname{radToDeg}(\delta_\odot)$$

$$\lambda_{\text{sub}} = \operatorname{wrap}_{180}(\operatorname{radToDeg}(\alpha_\odot - \text{gmstRad}))$$

- $\phi_{\text{sub}}$：太陽直下点の緯度（度、$[-90^\circ, +90^\circ]$）
- $\lambda_{\text{sub}}$：太陽直下点の経度（度、$[-180^\circ, +180^\circ)$、東経が正）
- $\operatorname{wrap}_{180}(\theta)$：角度を $[-180^\circ, +180^\circ)$ に折り返す正規化関数

北極点（$\phi = +90^\circ$）の太陽高度角は幾何学的に太陽赤緯 $\delta_\odot$ に等しくなるため、北極点の状態 `northPoleDaylightState` は太陽赤緯の度数 $\delta_{\deg} = \operatorname{radToDeg}(\delta_\odot)$ に応じて以下の3区分で判定する。

| 状態値 | 条件（設計基準） | 物理的意味 |
|---|---|---|
| `"polar-day"` | $\delta_{\deg} > +0.5^\circ$ | 太陽が常に地平線上にあり24時間昼（白夜） |
| `"equinox-transition"` | $-0.5^\circ \le \delta_{\deg} \le +0.5^\circ$ | 春分・秋分前後で太陽が地平線付近を周回する遷移期 |
| `"polar-night"` | $\delta_{\deg} < -0.5^\circ$ | 太陽が常に地平線下にあり24時間夜（極夜） |

### 2.5 都市の太陽高度・太陽方位角・現地地方太陽時

任意の地点（緯度 $\phi$、経度 $\lambda$、いずれもラジアン換算値）における `CityObservation` は、地方恒星時 $\text{LST}$ および太陽時角 $H$ を経由して計算する。

$$\text{LST} = \text{gmstRad} + \lambda$$

$$H = \operatorname{wrap}_{\pi}(\text{LST} - \alpha_\odot)$$

- $\text{LST}$：観測地点の地方恒星時（ラジアン）
- $H$：太陽の時角（ラジアン、$[-\pi, \pi)$ に正規化。南中時が $0$、午前が負、午後が正）

現地地方太陽時 `localSolarHours` $\in [0, 24)$（時間単位の地方視太陽時）は、$H = 0$ を正午 $12\text{h}$ として次式で算出する。

$$\text{localSolarHours} = \left(12 + \frac{H}{\pi} \cdot 12\right) \bmod 24$$

球面三角法により太陽高度角 $h$（`solarAltitudeDeg`）と太陽方位角 $A$（`solarAzimuthDeg`：北 $= 0^\circ$、東 $= 90^\circ$、南 $= 180^\circ$、西 $= 270^\circ$）を求める。各地点の East-North-Up（ENU）局所基底ベクトルとの内積から、象限ずれのない $\operatorname{atan2}$ 表記を用いる。

$$\sin h = \sin\phi \sin\delta_\odot + \cos\phi \cos\delta_\odot \cos H$$

$$h = \arcsin(\operatorname{clamp}(\sin h, -1, 1))$$

$$A_{\text{east}} = -\cos\delta_\odot \sin H$$

$$A_{\text{north}} = \cos\phi \sin\delta_\odot - \sin\phi \cos\delta_\odot \cos H$$

$$A = \operatorname{wrap}_{360}(\operatorname{radToDeg}(\operatorname{atan2}(A_{\text{east}},\; A_{\text{north}})))$$

- $h$：太陽高度角（ラジアン、度変換した値が `solarAltitudeDeg`）
- $A_{\text{east}}$：太陽方向ベクトルの局所東方向成分
- $A_{\text{north}}$：太陽方向ベクトルの局所北方向成分
- $A$：太陽方位角（度、$[0^\circ, 360^\circ)$）
- $\operatorname{clamp}(v, -1, 1)$：数値 $v$ を $[-1, 1]$ の範囲に制限する関数（浮動小数点誤差による `NaN` 防止）
- $\operatorname{wrap}_{\pi}(\theta)$：ラジアン角を $[-\pi, \pi)$ に正規化する関数
- $\operatorname{wrap}_{360}(\theta)$：度数角を $[0^\circ, 360^\circ)$ に正規化する関数

北極点（$\phi = +90^\circ$）では物理的な東西南北が定義上すべて南向きに退化する特異点となるため、上記式では $\lambda = 0^\circ$ を基準とした基準経線方向に対する角度が返る（UI 上では北極点が特異点である旨を補足表示して扱う）。

算出した `solarAltitudeDeg` および `solarAzimuthDeg` から、昼夜区分と16方位文字列を次のように決定する。

| 項目 | 規則・計算方法 | 出力例 |
|---|---|---|
| `daylightPhase` | `solarAltitudeDeg > 0`：`"day"`<br>`-6 <= solarAltitudeDeg <= 0`：`"twilight"`（常用薄明）<br>`solarAltitudeDeg < -6`：`"night"` | `"day"` / `"twilight"` / `"night"` |
| `solarDirectionJa` | $\lfloor (A + 11.25^\circ) / 22.5^\circ \rfloor \bmod 16$ を配列 `["北", "北北東", "北東", "東北東", "東", "東南東", "南東", "南南東", "南", "南南西", "南西", "西南西", "西", "西北西", "北西", "北北西"]` で参照 | $112.5^\circ \to$ `"東南東"` |

### 2.6 恒星日と太陽日の差・太陽が東から昇る理由

本アプリで扱う2種類の「1日」の定義と差は以下の通りである。

| 指標 | 基準 | 自転角度 | 所要時間 |
|---|---|---|---|
| **1恒星日（Sidereal Day）** | 遠方の恒星・春分点に対して同じ向きに戻る周期 | $360^\circ$ | 約 $86{,}164.09\text{ 秒}$（約 $23\text{時間}56\text{分}04\text{秒}$） |
| **1太陽日（Mean Solar Day）** | 太陽に対して同じ子午線（南中）に戻る平均周期 | 約 $360.9856^\circ$ | $86{,}400\text{ 秒}$（$24\text{時間}00\text{分}00\text{秒}$） |

1恒星日のあいだに地球は公転軌道上を反時計回りに約 $360^\circ / 365.2422\text{ 日} \approx 0.9856^\circ$ 移動する。そのため、恒星に対して $360^\circ$ 自転しただけでは、太陽の位置が前日より約 $0.9856^\circ$ 東（反時計回り方向）へずれて見える。太陽を再び同じ子午線上に捉えるには追加で約 $0.9856^\circ$ 自転する必要があり、この追加自転に約 $235.91\text{ 秒}$（約 $3\text{分}56\text{秒}$）を要する。

また、ある都市から太陽が東から昇り西へ沈む理由は、地表における「東」の向き（経度が増える向き）が地球の自転方向（反時計回り）と一致しているためである。夜の側にある地点が自転によって東向きへ回転して昼夜の境界（夜明け線）を通過するとき、進行方向前方にあたる東の地平線側から太陽光が差し込み、正午（南中、南半球中緯度では北中）を経て、さらに東へ回転するにつれ太陽は進行方向後方の西へ傾いていく。

### 2.7 月の軌道・満ち欠け・白道傾斜（`MoonState`）

任意の UTC 時刻（J2000.0 からの経過日数 $D$）と太陽視黄経 $\lambda_\odot$ から、天文年鑑の簡易月位置式（精度約 $0.3^\circ$）を用いて月の黄道座標と満ち欠け状態を算出する。

- **基本周期・軌道定数**：
  - 恒星月（恒星に対する公転周期）：$27.321661\text{ 日}$
  - 朔望月（新月から次の新月までの満ち欠け周期）：$29.530588853\text{ 日}$
  - 白道傾斜角（黄道面に対する月の軌道傾斜角）：$5.145^\circ$
- **黄経 $\lambda_m$・黄緯 $\beta_m$・昇交点黄経 $\Omega$**：
  - 平均黄経 $L_m = (218.316 + 13.176396 \cdot D) \bmod 360$
  - 平均近点角 $M_m = (134.963 + 13.064993 \cdot D) \bmod 360$
  - 昇交点からの平均引数 $F = (93.272 + 13.229350 \cdot D) \bmod 360$
  - 太陽平均近点角 $M_\odot$ と月太陽平均離角 $D_m = L_m - L_\odot$ の主要摂動項（中心差・出差・二均差）を加えて黄経 $\lambda_m$ を算出し、黄緯 $\beta_m = 5.128 \sin F$、昇交点黄経 $\Omega = (L_m - F) \bmod 360$ を得る
- **月相角・輝面比・月齢**：
  - 月相角 $\psi = (\lambda_m - \lambda_\odot) \bmod 360$（$0^\circ$: 新月、$90^\circ$: 上弦、$180^\circ$: 満月、$270^\circ$: 下弦）
  - 輝面比 $k = \dfrac{1 - \cos\psi}{2} \in [0, 1]$
  - 月齢目安 $= (\psi / 360) \times 29.530588853$
- **3D 表現と日食・月食シミュレーション**：
  - 地球中心の黄道座標系に半径 `MOON_ORBIT_RADIUS = 3.45`、月半径 `MOON_RADIUS = 0.27` で配置し、常に表側（嵐の大洋・雨の海・静かの海など）が地球へ向く潮汐ロック回転（`rotation.y = lonRad + π`）を適用する
  - 太陽光は遠方からの平行光線（地球-太陽単位ベクトル `sunDirWorld`）で照明し、夜側には淡い地球照（Earthshine）を描画することで、上弦・下弦の正確な半月と満ち欠けを再現する
  - **満ち欠けの補助線（月観察視点）**：「太陽の真上」視点の4季節マーカー・太陽-地球動径ラインの月の版として、次の補助線を描く
    - **満ち欠けの4点**：白道リングの上に、月相角 $\psi$ が $0^\circ$・$90^\circ$・$180^\circ$・$270^\circ$ になる位置へ「新月 (0°)」「上弦 (90°)」「満月 (180°)」「下弦 (270°)」の目印（小さな球）と名前の札を置く。定義は `MOON_PHASE_POINTS`（[calculations.ts](../src/astronomy/calculations.ts)）
    - 4点の黄経は $\lambda_\odot + \psi$ で、太陽の向きに合わせて毎フレーム地球のまわりを回る。新月は太陽の方向、満月は太陽と反対の方向にある。月は北から見て反時計回り（黄経が増える向き）に公転するので、上弦は太陽の方向から反時計回りに $90^\circ$ 進んだ位置（太陽の東側。夕方に南の空に見える半月）、下弦は $270^\circ$ 進んだ位置（太陽の西側）になる
    - 目印は白道の上に乗せる。その黄経での白道の黄緯 $\beta$ は $\tan\beta = \tan i \cdot \sin(\lambda - \Omega)$（$i = 5.145^\circ$、$\Omega$ は昇交点黄経）で求める（`getMoonOrbitLatitudeDeg`）
    - 目印の色は新月が暗め（`#94a3b8`）、上弦・下弦が中間（`#cbd5e1`、白道リングと同じ）、満月が明るい（`#f8fafc`）。札（`.space-badge.is-moon-phase`）は白道の少し内側（地球側に `0.55`）に出し、白道の外にある「☀ 太陽」の札や画面の端と重ならないようにする。月が目印の近くにいて、満ち欠けの札が「☾ 月」の札や月の本体に画面上で重なる（すき間 `6px` 未満）ときは、その札だけを隠す（「☾ 月」の札にいまの月相の名前が出るため）。重なりは、札が占める範囲の見積もり（`MOON_BADGE_SCREEN_BOX`・`MOON_PHASE_BADGE_SCREEN_BOX`）と画面上の月の半径を使い、px 単位で調べる
    - **地球から太陽の方向の線**：地球の中心から新月の目印まで、太陽-地球動径ラインと同じ琥珀色（`#fbbf24`）の細い線を引く。不透明度は、太陽-地球動径ライン（`0.28`）より少し濃い `0.42` にする（月の視点では線が短く、`0.28` では暗い背景の中で見分けにくいため）。既存の地球-月動径線とのなす角が、そのまま月相角 $\psi$ になる
    - **表示条件**：`moonAndOrbit` レイヤーが有効で、月観察の距離（地球近接でも太陽中心の公転俯瞰でもない、カメラ距離 `7.5` 以上）にあり、カメラが黄道面から $25^\circ$ 以上離れて見下ろしている（または見上げている）ときだけ表示する。`"moonNorthPole"` では表示し、黄道面を真横から見る `"moonEclipticPlane"`、リアル太陽系モード、地球近接・地上・黄道・太陽中心の視点では表示しない
  - **日食（`solarEclipseType`: `"total"` / `"annular"` / `"partial"`）**：白道と黄道の交点付近（$|\beta_m|$ が小）で新月（$\Delta\lambda \approx 0^\circ$）になった際、平均近点角 $M_m$ による見かけの視直径比 `apparentSizeRatio` $= 1.0 + 0.075 \cos M_m$ に応じて、近地点側（$\ge 1.0$）では太陽を完全に覆い昼空の減光とコロナ拡大を伴う**皆既日食**、遠地点側（$< 1.0$）では太陽外縁が金の輪として残る**金環日食**、中心からやや離れた領域では**部分日食**と判定・描画する。宇宙視点の地球昼面にも月の本影・半影スポット（`uSolarEclipseSpot`）を描画する
  - **月食（`lunarEclipseType`: `"total"` / `"partial"` / `"penumbral"`）**：交点付近で満月（$\Delta\lambda \approx 180^\circ$）になった際、対日照点（地球の影の中心）からの角度距離に応じて、地球の本影（半径約 $0.73^\circ$）に全体が入って大気屈折光で赤銅色に染まる**皆既月食**、本影に一部が入って丸く欠ける**部分月食**、外側の半影（半径約 $1.50^\circ$）のみを通過して片側が淡く減光する**半影月食**を月面フラグメントシェーダー（`uLunarEclipse`）および SVG 満ち欠け図で連続的に描画する

### 2.8 金星の公転軌道と見え方（`VenusState`）

J2000.0 の平均軌道要素（NASA JPL / Astronomical Almanac 準拠）を用い、任意の UTC 時刻から内惑星である金星の日心・地心黄道座標および地球からの見え方を算出する。

- **基本軌道定数**：
  - 軌道長半径：$a_v = 0.723332\text{ AU}$（地球 $= 1.0\text{ AU}$）
  - 恒星公転周期：$224.7008\text{ 日}$（平均日運動 $1.60213034^\circ/\text{日}$）
  - 軌道傾斜角：$3.3947^\circ$、昇交点黄経 $\Omega_v = 76.68^\circ$、離心率 $e_v = 0.006773$
- **地球からの見え方（離角・輝面比・明け/宵の明星）**：
  - 日心座標 $\vec{r}_v$ と地球の日心座標 $\vec{r}_E$ の差 $\vec{d} = \vec{r}_v - \vec{r}_E$ から地球-金星距離（`distanceAu`、約 $0.28\text{〜}1.72\text{ AU}$）および地心黄経・黄緯を求める
  - 太陽からの符号付き離角 `elongationDeg` $= \operatorname{wrap}_{180}(\lambda_{geo} - \lambda_\odot)$（常に約 $\pm 47^\circ$ 以内）により、東側（プラス）を **「宵の明星（西の空）」**、西側（マイナス）を **「明けの明星（東の空）」**、$|\text{離角}| < 8^\circ$ を **「内合付近」／「外合付近」** と判定する
  - 金星から見た太陽と地球のなす位相角より輝面比 `illumination` を算出し、太陽中心公転ビュー（軌道半径 `VENUS_ORBIT_RADIUS = 8.9`）および東京の地上視点（真の地心方向へ視差補正配置＋輝きスプライト）の双方に表示する
  - **太陽の真上視点での満ち欠け補助線**：`"sunOverhead"` 視点（`pitch > 65°`）では、月および金星の中心を通る「地球→天体の視線に直交（地球に対して平行）なシアン色の断面補助線」と、地球-金星間の破線視線ガイドを表示し、地球から見える半球の明暗割合を直接読み取れるようにする
  - **「地点・天体」パネルのリアルタイム満ち欠けイラスト（`CelestialPhaseDiagram.tsx`）**：月と金星の現在の輝面比および光る側（北半球基準で満ちていく月・宵の明星は右側、欠けていく月・明けの明星は左側）を SVG でリアルタイム描画し、金星は地球距離 `distanceAu` に反比例した見かけの大きさ（視直径）の変化も点線目安円とともに表現する

### 2.9 リアル太陽系モード（水金地火木土天海冥＋地球の月・木星主要4衛星）

[src/astronomy/solarSystem.ts](../src/astronomy/solarSystem.ts) において、NASA JPL J2000.0 の平均ケプラー軌道要素（軌道長半径 $a$・離心率 $e$・軌道傾斜角 $i$・昇交点黄経 $\Omega$・近日点黄経 $\varpi$・平均黄経 $L_0$・平均日運動 $n$）を用い、ニュートン法でケプラー方程式 $M = E - e \sin E$ を解いて 9 天体の 3D 日心黄道座標を 1 AU 比例縮尺（`1 AU = 13.5` 単位）で再現する。

- **収録天体（9天体）**：水星（$0.39\text{ AU}, e=0.206, i=7.0^\circ$）、金星（$0.72\text{ AU}$）、地球（$1.00\text{ AU}$、月付き）、火星（$1.52\text{ AU}, e=0.093$）、木星（$5.20\text{ AU}$、大赤斑・主要4衛星付き）、土星（$9.58\text{ AU}$、$26.7^\circ$ 傾斜の同心円リング付き）、天王星（$19.22\text{ AU}$、$97.8^\circ$ 横倒し環付き）、海王星（$30.11\text{ AU}$）、冥王星（$39.48\text{ AU}, e=0.249, i=17.16^\circ$、トンボー地域付き）
- **木星の主要4衛星（ガリレオ衛星）**：イオ（周期 `1.769日`）、エウロパ（`3.551日`）、ガニメデ（`7.155日`）、カリスト（`16.689日`）の $1:2:4$ ラプラス共鳴を含む公転位相を計算し、木星の赤道面上に4本の軌道リングと衛星メッシュを描画する
- **視点プリセット**：`"solarInner"`（内惑星・水金地火＋月）、`"solarJupiter"`（木星へ接近し主要4衛星を観察）、`"solarFullTop"`（水〜冥王星全体・真上）、`"solarFullOblique"`（水〜冥王星全体・斜め、冥王星の $17.16^\circ$ 軌道傾斜を立体表示）を「視点移動」カードから簡易版と連続的に切り替えられる（倍速には外惑星観察向けの **`1年/s`** も追加）

#### 天体の大きさ（表示半径）

リアル太陽系モードの間は、地球・月を含む全惑星と木星の4衛星を「実際の半径 × 共通の倍率」で描き、惑星どうしの大きさを実際の比率にそろえる。値は [src/astronomy/bodySizes.ts](../src/astronomy/bodySizes.ts) の1か所で管理する。

- **共通の倍率**：`REAL_SOLAR_PLANET_SCALE` ＝ 3.1 ÷ 11.21 ≒ 0.277（木星の表示半径をこれまでと同じ 3.1 に保つ値）
- **表示半径の計算**：実際の半径（地球の赤道半径 6,378 km ＝ 1。冥王星と衛星は平均半径）× `REAL_SOLAR_PLANET_SCALE`（シーン単位は簡易モードの地球の半径 ＝ 1）
- **太陽**：実際の比率（地球の約109倍）で描くと水星の軌道まで覆うため、別の縮尺の `REAL_SOLAR_SUN_RADIUS` ＝ 3.4 で描画。木星（3.1）より大きく、水星が太陽にもっとも近づく位置（0.307 AU ＝ 4.15）より内側に収まる値
- **遠景での拡大**：しない。太陽・惑星・衛星とも、カメラを寄せても引いても描く大きさは変えない（太陽はどの距離でも 3.4。遠景では水星・冥王星などが点に近くなる）
- **リアル太陽系以外の視点**：天の北極・地上・黄道ビュー・宇宙スケールでは、地球の半径 1・月の公転半径 3.45・金星の半径 0.78 のまま。視点の切り替えに合わせて、リアル太陽系の割合（`solarSystemBlend`）で滑らかに大きさを補間（地上・黄道ビューへ移る分はその割合で打ち消し）
- **一緒に縮むもの**：地球と月のまとまり（地球・大気・都市マーカー・月とその公転軌道。地球と月の大きさの比 0.273 と、公転半径 ÷ 地球の半径 ＝ 3.45 は変えない）、木星4衛星の大きさ（木星の模型の中で木星の半径との実比率）、土星・天王星の環（惑星の模型と一緒に拡大縮小）
- **衛星を描く距離**：衛星は実際の距離のままだと描いた母惑星の内側に入るため、「実際の距離 × 系ごとに1つの倍率」の位置に描く（同じ母惑星の衛星どうしの距離の比は実際のとおり。値は `bodySizes.ts` の `EARTH_SYSTEM_DISPLAY_FACTOR`・`JUPITER_SYSTEM_DISPLAY_FACTOR`）

### 2.10 地球から見る黄道と黄道12星座（へびつかい座を含む13星座）

[src/astronomy/zodiac.ts](../src/astronomy/zodiac.ts) において、国際天文学連合（IAU）の実際の星座境界（J2000.0・歳差反映後）に基づく **黄道13星座**（うお座・おひつじ座・おうし座・ふたご座・かに座・しし座・おとめ座・てんびん座・さそり座・**へびつかい座 [13番目の星座]**・いて座・やぎ座・みずがめ座）の主要恒星座標（J2000.0 赤経・赤緯を `equatorialToEclipticDeg` で黄道座標へ厳密変換）と星座線、通過黄経区間、通過時期目安を定義している。

- **地球中心の黄道ビュー（`"earthEclipticFollow"` / `"earthEclipticFixed"`）**：カメラを地球中心 `earthOrbitPos` へ滑らかに移動し（`FOV = 64°`、ドラッグで全周360°見渡し・ホイール/ピンチで FOV ズーム）、黄金の黄道大円（$10^\circ$ 目盛り・$30^\circ$ 西→東進行方向矢印・春分点/夏至点/秋分点/冬至点）、$23.44^\circ$ 傾いた天の赤道破線、13星座の恒星と星座線およびラベル、太陽の直近 $32^\circ$ 黄道軌跡を描画する。「太陽追尾」では太陽を中央に追いながら背景の13星座が巡り、「星座固定」では静止した星座の間を太陽が右から左（西→東）へ移動する様子を直接観察できる
- **太陽の真上・公転面（やや上）視点の黄道13星座3D配置**：`"sunOverhead"` および `"sunEclipticOblique"` 視点では、公転軌道の外周3D天球面上（半径 `24.5`）に13星座それぞれの主要恒星（3D点・発光球）とその点を結ぶ星座線（`edges`）を実際の黄経・黄緯方向に立体配置し、地球→太陽→現在の星座を結ぶ破線視線ガイドとハイライト表示によって、公転によって太陽の背景星座が変わる仕組みを立体的に結び付ける
- **カシオペア座（W字形）・南十字星（十字形）と星の年周運動観察モード（毎日21:00 JST固定）**：
  - 北半球（東京・ロンドン・ニューヨーク・トロムソ・北極点）および赤道（キト）の北の空で北極星（高度＝その地点の北緯）の周囲を反時計回りに巡る周極星座 **カシオペア座**（$\beta, \alpha, \gamma, \delta, \varepsilon\text{ Cas}$ の5星・4辺、J2000.0実座標）と `★ カシオペア座 (W字)` ラベルを配置する
  - 南半球（シドニー・南極点）および赤道（キト）の南の空で天の南極（高度＝その地点の南緯）の周囲を時計回りに巡る **南十字星（みなみじゅうじ座 / Crux）**（アクルックス・ミモザ・赤色巨星ガクルックス・イマイ・ギナンの5星・2交差辺、J2000.0実座標）と `✦ 南十字星 (みなみじゅうじ座)` ラベルを配置する
  - **年周運動モード（`snapDateToJstHour` / `applyAnnualFixedHourLock`）**：有効化すると時刻を `21:00 JST` に揃え、1日の自転回転成分（$2\pi \times \text{fracDay}$）のみを連続的に相殺することで、昼夜の点滅なしに毎日21時の星空のまま1日あたり約 $+0.9856^\circ$（1ヶ月で約 $30^\circ$）ずつカシオペア座・南十字星・黄道13星座が移動する年周運動を 60fps で滑らかに再現する（「+1ヶ月（同刻）」ステップボタンも提供）
- **「地点・天体」パネルの表示**：月と金星の満ち欠けの様子の絵（`CelestialPhaseDiagram.tsx` によるリアルタイム SVG）と状態の名前（`三日月`、`上弦の月`、`満月`、`明けの明星`、`宵の明星` など）のみをシンプルに表示する

### 2.11 万有引力・天体衝突シミュレーター（リアル太陽系モード）

リアル太陽系モードの空間へ、実在の天体をモデルにした10種類の天体（以下、投入天体）を種類を混ぜて何個でも続けて置き、太陽系の15天体と投入天体が互いの万有引力で動く様子と、衝突・吸収・合体を観察する機能。計算は [src/astronomy/impactPhysics.ts](../src/astronomy/impactPhysics.ts)、3D 演出は [src/scene/impactSystem.ts](../src/scene/impactSystem.ts) が受け持つ。

- **重力は実寸、当たりは描いた絵で判定**：
  - 重力・予測の計算は、太陽系の15天体も投入天体も、実際の質量・距離で実施（値は [src/astronomy/realBodyData.ts](../src/astronomy/realBodyData.ts)）
  - 画面に描くときだけ、天体を見える大きさに拡大し（2.9 の「天体の大きさ」）、衛星を母惑星のまわりに広げた位置に描画（[src/astronomy/displayWarp.ts](../src/astronomy/displayWarp.ts)）
  - 衝突は、太陽系の15天体も投入天体もすべて、画面に描いている位置と大きさで判定する。描いた絵どうしが触れたら当たり（観察パネルにも同じ説明を表示）：
    - 物理上の位置を、衛星のまわりを広げて描く変換で描く位置に直し、その距離が2天体の描く半径の和以下になったら当たり
    - 描く半径は 2.9 の「天体の大きさ」と、下の「画面に描く半径」の値（太陽系天体は `displayRadius`、投入天体は `visualRadius`）
    - 青色超巨星（リゲル。描く半径 約268）は、置いた瞬間に中にある太陽や惑星を飲み込むことがある。置く位置は実際の半径で決める

#### 操作

1. 「地点・天体」タブの「万有引力・天体衝突シミュレーター」で投入天体を選択（リアル太陽系以外の視点にいる場合は、太陽系を斜め上から見る視点へ移動）。このとき時間の倍速を 10日/s 以上にして再生
2. 1本指（左クリック）で画面を押して、置く位置を決定
   - そのまま離す（移動量 10px 未満）：押した位置に、太陽に対して止まった状態で置く（天体の上を押した場合は、その天体のすぐ近くに置く。「すぐ近く」の決め方は下記）
   - ドラッグして離す：ドラッグの向きと長さに応じた速度で投げ込む
3. 押している間は、予測軌道（破線）、軌道が乱れる惑星の予測軌跡、衝突が予測される天体のリングを表示。当たる投げ方は、このリングを目安に探す
4. 続けて押すと、すでに置いた天体を残したまま次の天体を追加。種類は画面右上の天体ボタン列（「天体を狙う」モード中だけ表示）で、観察パネルを開かずに切り替え
5. 「復活」ボタンで、置いた天体をすべて消し、太陽系の全天体を 3.2 秒かけて元の公転位置へ戻す

- 置ける数の上限：同時に 16 個（`MAX_LIVE_IMPACTORS`）。上限に達した状態で置くと、いちばん古い投入天体を消して追加
- 画面右上の「置いた天体 n/16」：今置かれている投入天体の数
- 投入天体のボタン：観察パネルの一覧ではモデルにした天体の名前・半径・質量を表示。右上のボタン列では、同じ内容をボタンの説明（ツールチップ）に表示
- 画面で狙った位置と向きは、描く位置から物理上の位置へ直して使う（衛星の近くでは、広げて描いた分を元に戻す）。速さはドラッグの長さで決まり、変換しない
- 天体の上を押したときの「すぐ近く」（天体の中心からの距離・描く空間）：次の2つのうち遠いほう（`nearBodySpawnClearance`）
  - 描いた絵が重ならない距離：天体の今の描く半径 × 1.9 ＋ 投入天体の描く半径 × 1.45 ＋ 1.4。天体の描く半径は画面で今描いている値（太陽はどの距離でも 3.4）。ただし巨大な恒星（描く半径が `HUGE_STAR_DISPLAY_RADIUS` ＝ 20 を超えるリゲル）の描く半径は足さない（足すと数百離れた位置になるため）
  - 実際の大きさが重ならない距離：2天体の実際の半径の和 × 1.5 だけ離れた物理上の点を、描く位置に直した距離。当たりは描く大きさで判定するので、当たりを避けるためのものではない。N体計算は天体を点として扱うため、実際の大きさより近くに置くと実際にはありえない強い重力がはたらく。その状態から計算を始めないためのもの

- **初期状態**：最初の天体を置いた瞬間の天体位置を使用
  - 惑星：ビス・ビバの式 $v = \sqrt{GM(2/r - 1/a)}$ による公転速度（$a$ は実際の軌道長半径）
  - 衛星：「母惑星の速度＋母惑星のまわりの円軌道の速さ」。描いている位置は広げた位置なので、母惑星からのずれを倍率で割って実際の距離に戻してから設定
  - 太陽：全体の運動量の合計が 0 になる速度（惑星に引かれて太陽も少し動く）
- **重力**：すべての天体の組で万有引力を計算。実際の値を使うので、以前の調整（衛星どうしの引力の省略、衛星への太陽の引力の調整、距離を少し大きく見なす softening）は廃止
- **時間の進め方**：
  - 物理の時間は、アプリの時間の進み方（倍速）に合わせて進め、一時停止中は止める（例：10日/s なら 1 秒で 約 0.25 シミュレーション時間）
  - 速度ベルレ法（キック・ドリフト・キック）で、1ステップの長さを天体の組ごとの「公転の時間の目安 √(r³/GM)」と「すれ違う時間 r/v」の最小値 × 0.1 に自動で調整（最大 0.02、最小 10⁻⁹ シミュレーション時間）
  - 例：イオは木星のまわりを 約 0.044 シミュレーション時間で1周するので、1周を 約 60 ステップで計算。テストで、約2年ぶん進めても月と4衛星の母惑星からの距離の変化が 5〜10% 以内であることを確認
  - 1フレームのステップ数の上限：4,000（`MAX_STEPS_PER_ADVANCE`）。ブラックホールのすぐ近くなどで上限に達すると、そのフレームはそこまでで止める（物理の時間が少し遅れる）
- **衛星を広げて描く範囲**（`SATELLITE_DISPLAY_SYSTEMS`）：

| 系 | 倍率どおりに広げる範囲（物理上の距離） | 変換しない外側の境目 |
|---|---|---|
| 地球と月 | 0.0451 まで（月の距離の 1.3 倍） | 1.55 |
| 木星と4衛星 | 0.221 まで（カリストの距離の 1.3 倍） | 33.7 |

- 広げる範囲と外側の境目の間は、位置が途切れないよう直線でつなぐ。投入天体・爆発・予測線もこの変換で描く位置に直すので、月を狙った天体は描いた月に向かって飛ぶ
- **母惑星が消えた場合**（地球と月の系・木星と4衛星の系で同じ）：その系の衛星が1つでも残っていれば、衛星を広げて描く変換を弱めずに残す
  - 理由：変換をなくすと衛星が実際の距離に戻り、描く半径の和のほうが衛星どうしの距離より大きくなるため、すぐにぶつかって1つにまとまる（以前は木星が消えると、`io<-europa`・`ganymede<-io`・`ganymede<-callisto` の衝突が続けて起きていた）
  - 変換の中心：生き残っている衛星たちの重心（`gravityGM` で重み付けした位置）と一緒に動く点。母惑星が消えた瞬間は母惑星の位置から始め、中心が飛ばないよう、その瞬間の重心とのずれ（母惑星の `satelliteWarp.offset`）を保つ。衛星が合体・消滅して重心が変わった瞬間も、同じようにずれを直す（ずれを足さずに重心へ移すと、木星の系では描く位置で最大 約12 も衛星がまとめて飛ぶため）
  - 衛星がすべて消えた場合：その直前の中心で止め（`satelliteWarp.frozenCenter`）、変換は残す。止めた中心から外側の境目（`outerRadius`）より内側に、生きている天体（投入天体を含む）が1つもいなくなったステップの終わりに、変換を外す（`satelliteWarp.ended`）。外側の境目より外では変換しても位置が変わらないので、外したときに何も飛ばない（すぐに外すと、衛星を飲み込んだブラックホールや恒星など、範囲の中にいる天体の描く位置が1フレームで最大 約20 飛ぶため）。一度外した変換は使わない
  - 消えた天体（母惑星・衛星）は、消えた瞬間の描く位置にとどめて、縮んで消える演出を描く。注視しているカメラもその位置から動かない（変換の中心が動いても、消えた天体の絵は動かさない）
  - 当たり判定（`FlatNBodySystem.hostsAt`・`computeDrawnPositions`）と画面（`snapshotSatelliteHosts`）は同じ関数（`resolveSatelliteHost`）で中心を決め、変換を外すかどうかも同じ状態（母惑星の `satelliteWarp`）で決める。予測（`SolarNBodyPredictor`）・爆発の位置・予測線も同じ変換を使うので、予測と実際の進行で同じ判定になる
  - 見え方：衛星は母惑星の重力がなくなった方向（それまでの公転の向き）へまっすぐ飛び、描く位置ではその動きも倍率どおりに広げて見える。広げる範囲の外へ出るとつなぎの部分で動きがゆっくりになり、外側の境目より外では実際の位置に描く
  - 「復活」：N体計算の状態を作り直すので、変換の中心も母惑星の中心に戻る

#### 衝突の判定と結果

- **衝突とみなす距離**：2天体の描く位置（物理上の位置を、衛星を広げて描く変換で直した位置）の距離が、2天体の描く半径の和以下（描いた絵どうしが触れたら当たり）
- **すり抜けを防ぐ判定（スイープ判定）**：各ステップで2天体の描く位置がステップの始めから終わりまでまっすぐ動いたとみなし、ステップの間にいちばん近づいた距離が「衝突とみなす距離」以下なら衝突とする。衝突の時点は初めてその距離になった時点で、触れた点は残るほうの天体の実際の半径の表面の点
- **結果**：重いほう（`gravityGM` が大きいほう）が残り、軽いほうを取り込む。ブラックホールは相手の重さによらず取り込む
- **対消滅**：同じ天体どうしがぶつかると、両方とも消える（重さも残らない。`SolarCollisionEvent.annihilation` が true）
  - 同じ種類の投入天体どうし（例：リゲルとリゲル、ブラックホールとブラックホール）
  - 投入天体と、そのモデルにした太陽系の天体（月サイズと月、火星サイズと火星、木星サイズと木星、太陽クラス恒星と太陽）
  - 一度ほかの天体を取り込んだ天体も、元の種類のまま判定する（例：月サイズを取り込んだ地球は地球）
  - 残ったほうの速度：2天体の速度の `gravityGM` 比の平均（運動量保存）
  - 残ったほうの重さ：2天体の重さの合計（質量保存）
  - 例：小惑星が地球に当たると地球が残り（クレーターと赤熱を表示）、木星サイズが地球に当たると地球が取り込まれて消える
- 予測軌道と実際の進行は同じ計算（ステップの決め方・スイープ判定）を使用
- 爆発の見た目：投入天体が関わる衝突はその投入天体（投入天体どうしは残ったほう）の種類、太陽系天体どうしの衝突は置いた天体に関係なく火星サイズの天体の衝突と同じ見た目
- 爆発を出す位置：
  - 2天体の触れた瞬間の中心を、その瞬間の変換の中心（ふつうは母惑星の位置）で描く位置に直す（フレームの終わりの位置で直すと、10日/s で地球 約1、木星 約2 ずれるため）
  - 描く半径が小さいほうの天体が描かれていた位置で爆発させる（例：リゲルが地球を取り込むと、地球が描かれていた位置で爆発）
  - ただし、その位置が不透明に描いた大きいほうの天体の内側なら、隠れないよう大きいほうの表面まで押し出す（例：地球に当たる小惑星は、描いた地球の表面で爆発）。リゲルに飲み込まれた天体も、リゲルの表面で爆発
  - 対消滅は、2天体の描く位置のまん中で爆発させる
  - リゲル自身が消えるとき（ブラックホールに取り込まれる・リゲルどうしの対消滅）は、消えるリゲルの中心（対消滅ならまん中）で爆発させる
  - 描く半径は、その天体を今描いている値を使う
- 爆発の大きさ：ぶつかった2天体の描く半径の和 × 0.85（最小 0.2・最大 5.5）に比例
  - 例外：リゲル自身が消えるときは、火球のいちばん大きいときの半径がリゲルの描く半径（約268）と同じになる大きさにし、破片と火花もリゲルの大きさまで飛び散る速さにする（速さを大きさの平方根ではなく、大きさに比例させる）
- 同時に描画する爆発（火球・衝撃波リング・閃光）：最大 6 個。7 個目からは、いちばん古い爆発の表示を使い回す
- ブラックホール・中性子星の衝突で飛び散った破片：その天体の描く位置へ吸い込まれ、天体が消えた後は爆発の中心へ移動
- 木星が消滅した場合：木星本体と4衛星の軌道リングだけを隠し、4衛星は消滅するまで N体計算の位置を広げて描く変換で直した位置に描画（押下の対象にも残す。変換の中心は「衛星を広げて描く範囲」の「母惑星が消えた場合」）

#### 予測軌道

- 押している間、現在の状態（N体計算の途中なら、乱れた後の位置・速度と、すでに置いた投入天体を含む）を複製し、3.0 シミュレーション時間（約4か月）先まで計算。180 点の予測線として表示
- 計算の分け方（操作中に重くならないように）：
  - 指を動かしたとき（pointermove）は最新の狙いを覚えるだけで、予測は1フレームに最大1回だけ始める
  - 1フレームで予測に使う時間は 4 ミリ秒まで（`PREDICTION_TIME_BUDGET_MS`）。64 ステップごとに時間を確かめ、使い切ったら次のフレームで続きを計算し、途中までの予測線もそのつど表示
  - 指を動かし続けている間は、狙いが変わるたびに予測を作り直すため、予測線は最初の 4 ミリ秒で計算できた分だけ（置いた天体が多いほど短い）。指を止めると数フレーム（4〜14 フレーム程度）で最後まで計算され、後半で当たる天体のリングも表示される
  - 計算途中の予測は、発射・取り消し・リセット・「復活」のときに止めて消す
  - 置いた天体が多いほど予測を終えるまでのフレーム数は増えるが、1フレームの重さは増えない
- 予測の計算は複製した状態で行い、実際の天体の位置・速度は変更しない
- 予測1回のステップ数の上限：9,000（操作中に重くならないように。上限に達したらそこで予測を終了）
- 予測線の各点はその点の時点の変換の中心で、当たる天体のリングは衝突した瞬間の変換の中心で、描く位置に直して表示（当たり判定と同じ変換）
- 当たる天体のリングの位置と大きさは、その天体を今描いている半径に合わせる
- 惑星の予測軌跡は、木星の質量の半分以上の投入天体（木星サイズ・恒星・中性子星・ブラックホール）のときだけ表示
- 小惑星〜木星サイズ（規模ティア 1・2）は、これから置く天体が消滅した時点で予測を終了

## 3. 表示・操作仕様

### 3.1 ビジュアル表現と画面レイアウト

- **宇宙リアル専用**：緯度別の気候帯カラー、`world-atlas` / `topojson-client` による海岸線・陸地マスク、夜景の都市灯り、薄明（トワイライト）、海洋の鏡面反射、大気リムライト、恒星背景を常時描画する（「天文図解」モードは廃止）。

- **ゆっくり滑らかな連続トランジション**：プリセット切り替え時は、現在の姿勢を始点として 3 次イージング（`easeInOutCubic`）と対数距離補間（$\exp(\operatorname{lerp}(\ln d_0, \ln d_1))$）・クォータニオン球面線形補間（`slerp`）を用い、東京地上の方位旋回は `1.8 秒`、宇宙の同一距離帯内は `2.6〜2.8 秒`、宇宙 ⇄ 東京地上や距離帯を跨ぐ移動は `3.0〜3.6 秒` かけて連続的に視点移動する
- **東京地上視点の視差補正と大気表現**：地上視点へ降りるにつれ、地球半径による視差ズレを防ぐため太陽・月・星空を遠方天球位置へ滑らかに押し出し、太陽高度に応じた大気スカイドーム（昼の青空・朝夕焼け・夜の星空透過）、地平線遮蔽ディスク、遠景シルエット、8方位ラベル、高度 $35.7^\circ$ の北極星目印を描画する
- **天の北極 ⇄ 公転面（水平）連続スライダー**：`0%`〜`100%` のスライダー操作で `eclipticBlend`（`0 -> 1`）と `pitch`（`90° -> 0°`）を連続補間し、地球クローズアップ距離でも月観察距離でも途中の任意の角度へ移動できる
- **視点に応じた再生倍率の自動調整**：月観察視点（`"moonNorthPole"` / `"moonEclipticPlane"`）または太陽公転視点（`"sunOverhead"` / `"sunEclipticOblique"`）へ移動した際に速度が `1日/s` 未満であれば公転のデフォルト速度 **`1日/s`（`86400×`）** へ切り替え、地球近接視点・東京地上視点へ戻った際に `1日/s` 以上であれば自転・日周運動が見やすい `30分/s`（`1800×`）へ戻す（手動での倍率変更も可能）
- **6DOF（6自由度）カメラ操作**：
  - **回転3自由度（Yaw / Pitch / Roll）**：左ドラッグまたは矢印キーで方位角・仰角回転、`Alt/Option + 左ドラッグ`・`Q`/`E` キー・タッチ2本指ひねりで光軸周りのロール回転が可能
  - **平行移動3自由度（Pan X / Pan Y / Dolly Z）**：右ドラッグ・中ボタンドラッグ・`Shift + 左ドラッグ`・タッチ2本指スワイプでカメラ平面内の平行移動、ホイール・2本指ピンチで前後移動、`W`/`A`/`S`/`D`（前後左右）・`R`/`F`（上下）キーで連続自由飛行が可能（プリセット選択時は平行移動オフセットとロール角も滑らかに `0` へ補間リセットされる）
- **マルチデバイス・レスポンシブ対応（セーフエリア `viewport-fit=cover` + `env(safe-area-inset-*)` 対応）**：

### 3.5 時間操作と季節プリセット

- **再生 / 一時停止**：自転・公転アニメーション進行の開始と停止の切り替え
- **現在時刻（「今」）への同期**：システム現在時刻（UTC）への即時同期
- **倍速設定**：
  - 自転・日周運動観察向け：`1× (実時間)`、`30分/s`（`1800×`）、`2時間/s`（`7200×`）
  - 公転・年周運動・太陽系観察向け：`1日/s`（`86400×`）、`10日/s`（`864000×`）、`30日/s`（`2592000×`）、`1年/s`（`31557600×`）
- **年周運動（毎日21時固定）トグル**：`年周(21時)` ボタンで毎日 21:00 JST の星空にロックし、公転に伴う星の年周運動を観察（観察パネル内に `+1ヶ月 (同刻)` ボタンも配置）
- **速度連動スケーリング・タイムスライダー（`getTimeSliderScale`）**：再生速度に応じてレンジと刻み幅を自動スケーリングし（`1×〜2時間/s`: `1日`・1分刻み、`1日/s`: `1ヶ月`・2時間刻み、`10日/s〜30日/s`: `1年`・1日刻み、`1年/s`: `50年`・約1ヶ月刻み）、どの速度でもつまみが約 `12〜50 秒` で落ち着いて1周する操作感を実現
- **季節プリセット（滑らかな時間前進）**：春分（3月20日頃）・夏至（6月21日頃）・秋分（9月23日頃）・冬至（12月21日頃）ボタンを押すと瞬間ジャンプせず、現在日時から未来方向へ次に訪れる目標季節（`getNextSeasonDate`）まで、日数に応じた `1.8〜5.2 秒` の 3 次イージング（`easeInOutCubic`）で連続的に時間を進める（一時停止中でも滑らかに進行し、到達後は元の再生状態を維持）

### 3.8 実績（体験チェックリスト）

アプリで体験してほしい操作を23個の実績としてまとめ、達成状況をユーザーのブラウザに保存する機能。未達成の実績も「やること」を表示し、次に試す操作の道案内とする。23個のうち1個は、達成するまで名前を隠す「シークレット」の実績とする。定義は [src/achievements/definitions.ts](../src/achievements/definitions.ts)、判定は [src/App.tsx](../src/App.tsx)、表示は [src/components/AchievementList.tsx](../src/components/AchievementList.tsx) と [src/components/AchievementToast.tsx](../src/components/AchievementToast.tsx) が受け持つ。

#### 表示

- **一覧**：観察パネルの4つ目のタブ「実績」（トロフィーのアイコン）
  - 進捗（`n/23`）と進捗バー。全体の数は定義（`ACHIEVEMENTS`）の個数で、シークレットの実績も含む
  - 7分類ごとの実績名、やること、達成済みの印
  - 「〇種類」の実績は、未達成のあいだ今の累計（例：`2/5`）を表示
  - 「同時に〇個」の実績は、未達成のあいだこれまでの最大記録（例：`3/5`）を表示
  - シークレットの実績は、未達成のあいだ実績名を `？？？` で表示（下の「シークレットの実績」を参照）
- **達成通知**：達成した瞬間に、画面上部の中央へ「実績解除：（実績名）」を約3秒表示して自動で消去
  - 同時に複数達成した場合は、1件ずつ順番に表示
  - クリック・タップは通知の下の画面へ素通り（3D 画面の操作を妨げない）
  - 幅 640px 以下では、右上のボタン列と重ならないようボタン列の下に表示
- **記録を消す**：「実績」タブの最下部のボタン。確認ダイアログで「OK」を選ぶと、保存データと表示中の通知をすべて消去

#### 実績一覧と達成条件

視点に関する実績は、操作の種類（プリセットボタン・視点スライダー・学習ガイド）ではなく、カメラの移動先の視点（`cameraPoseTarget`）で判定する。どの操作で移っても、同じ条件で達成とするため。

| 分類 | 実績名（id） | 達成条件 |

| 地球の自転・昼夜 | 季節を旅する（`jump-to-season`） | 画面下の季節ボタン（春分・夏至・秋分・冬至）を押下。学習ガイドの実験（`ecliptic-tilt` など）による季節の移動では未達成 |

#### ドパガキ（リゲルを同時に5つ）の数え方と達成のしかた

- **数えるとき**：天体を置いた（発射した）直後、次のフレームの衝突の判定より前
  - [src/scene/impactSystem.ts](../src/scene/impactSystem.ts) の `countLiveImpactorsOfType` で、今置かれていて消えていない（`alive`）投入天体のうち、置いた天体と同じ種類の数を数える（今置いた1個を含む）
  - [src/scene/EarthGlobeCanvas.tsx](../src/scene/EarthGlobeCanvas.tsx) が `onImpactorLaunched(天体の種類, 同じ種類の数)` で App へ伝え、App が実績の出来事 `place-impactor` として記録する
- **進捗**：リゲルを置くたびに、数えた数がこれまでの最大記録（`progress.maxSimultaneousRigels`）より大きければ更新する。最大記録が5以上になったら達成
  - 対消滅などで数が減っても、最大記録は下げない
- **数え方の理由**：リゲルは描く半径が 約268 と巨大で、衝突は描く大きさで判定する。同じ天体どうしは対消滅する（[src/astronomy/impactPhysics.ts](../src/astronomy/impactPhysics.ts) の `mergePair`）ため、物理の時間が進むと、近くに置いたリゲルどうしはすぐに消える。衝突の判定より前に数えることで、置いた瞬間に5つそろえば達成とする
- **達成のしかた**（確実な方法）：
  1. 「天体を狙う」モードで、天体の種類から青色超巨星（リゲル）を選ぶ（選ぶと自動で再生になる）
  2. 画面下の一時停止ボタンで、時間を止める
  3. リゲルを5回置く（同じ場所でもよい）。一時停止中（倍速 0）は物理の時間が進まず（`advanceSolarNBody` は進める時間が 0 以下なら何もしない）、衝突が起きないので、5つとも残る
  4. 5つ目を置いた瞬間に達成。再生に戻すと、重なったリゲルどうしは対消滅する
- 再生中でも、すでに4つ生きているところへ5つ目を置けば、その瞬間に達成する（置いた直後に重なって対消滅しても、数えたあとなので達成は残る）

#### 保存形式

ブラウザの `localStorage` に、キー `polaris.achievements.v1` で JSON を保存する（[src/achievements/storage.ts](../src/achievements/storage.ts)）。記録はそのブラウザだけに残り、他の端末やブラウザとは共有しない。

| 項目 | 型 | 内容 |
|---|---|---|
| `version` | `1` | 保存形式の版 |
| `unlocked` | `{ [実績id]: 文字列 }` | 達成した実績と達成日時（ISO 8601 形式、例：`2026-11-19T10:08:41.313Z`） |
| `progress.openedBodyIds` | 文字列の配列 | 解説カードを開いた天体の id（重複なし） |
| `progress.placedImpactorIds` | 文字列の配列 | 衝突シミュレーターで置いた天体の種類の id（重複なし） |
| `progress.maxSimultaneousRigels` | 0 以上の整数 | これまでに同時に置けたリゲルの数の最大値 |

- `progress.maxSimultaneousRigels` は23個目の実績と一緒に追加した項目。キーと版（`polaris.achievements.v1`、`version: 1`）は変えず、この項目がない古い保存データは 0 として読み込む

- 読み込みのタイミング：
  - アプリの起動時
  - 実績を判定する操作のたび（保存データを読み直し、その内容に操作を反映）
  - ほかのタブで保存データが更新・消去されたとき（`storage` イベント）
- 保存のタイミング：実績の達成または累計の更新があった操作の直後

#### 複数のタブで開いた場合

- **記録の更新**：保存データが画面の状態と一致している間は、操作のたびに保存データを読み直し、その最新の内容に操作を反映して保存。画面が持つ古い状態で丸ごと上書きしないため、ほかのタブで増えた実績を消さず、ほかのタブの「記録を消す」も取り消さない（保存に失敗した後の扱いは「失敗時の動作」を参照）
- **表示の同期**：ほかのタブで記録が更新・消去されると、`storage` イベントで保存データを読み直し、「実績」タブの一覧と進捗に反映。ほかのタブで達成した実績の通知は表示しない

#### 失敗時の動作

- **`localStorage` が使えない場合**（プライベートブラウズ、サイトデータの無効化など）：読み書きの例外を捕捉して、空の状態で動作を継続。実績はその画面を開いている間だけ、画面が持つ状態に記録
- **保存データが壊れている場合**：JSON として読めないデータは空の状態として扱い、次の保存で上書き
- **保存データは読めるが保存できない場合**（容量超過、古い Safari のプライベートブラウズなど）：
  - 保存に失敗した時点で、保存データを「画面の状態と不一致」として記録
  - 不一致の間は保存データを読み直さず、画面の状態（このタブで達成した分を含む）を土台に記録を継続。達成が画面から消えず、同じ実績の通知も重複しない
  - 不一致の間もほかのタブからの更新（`storage` イベント）は反映しない（保存データより画面の状態のほうが新しいため）
  - 以後の記録で保存に成功したら、一致の状態に戻り、読み直しを再開
- **「記録を消す」で保存データの削除に失敗した場合**：
  - 代わりに空の状態の上書き保存を試行し、成功すれば一致の状態
  - 上書き保存にも失敗した場合は「不一致」として、空になった画面の状態を土台に記録を継続。保存データに残った古い記録は読み直さないため、画面に戻らない
- **一部が不正な場合**：未知の実績 id、文字列でない達成日時、文字列でない累計の要素、重複した要素を捨て、正しい部分だけを読み込み。リゲルの最大数が 0 以上の整数でない（ない・負の数・小数・数でない）場合は 0 として読み込み

#### 押したときの判定

[src/scene/skyPicking.ts](../src/scene/skyPicking.ts) と `EarthGlobeCanvas.tsx` の `pickCelestialBodyAtClientPos` で、次の順に調べる。

1. **太陽系の天体・主要15恒星**：今までどおり、球（中心と半径）に当たるか、どの球にも当たらなければ画面上で中心から 14px 以内（`PICK_MIN_SCREEN_RADIUS_PX`）のいちばん近い天体
2. **星座の星**：1で何も選ばれなかったときだけ、画面上で星から 12px 以内（`SKY_STAR_PICK_RADIUS_PX`）のいちばん近い星。星座の星は点群（`THREE.Points`）で描いているため、球を作らず、画面に写した位置との距離で判定する
3. **星座の線・星座の形の線**：1・2で何も選ばれなかったときだけ、画面上で線から 8px 以内（`SKY_LINE_PICK_RADIUS_PX`）のいちばん近い線。星座の線と星座の形の線がほぼ重なるとき（秋の四辺形とペガスス座など）は、上に目立つ色で描いている星座の形を選ぶ（2px のおまけ）

- 太陽系の天体を先に調べるのは、細かい星が多い視点（太陽の真上の視点の公転軌道の外周の星座など）で、天体のすぐそばを押したときに星を選ばないようにするため
- 画面に描いていないグループ（非表示の星座・遠景）の星と線は選ばない。地上視点では、地平線より下の星と線も選ばない
- 名前の札（黄道13星座・季節の星座・星座の形・カシオペヤ座・南十字星・北極星・宇宙の構造）は、押すと解説カードが開くボタンにする。北極星の札は北半球だけ押せる（南半球では「天の南極」の札で、星がないため）
- 解説カードを開くと、星はその星の位置へ寄る。星座と星座の形は、天球の中心側から正面に見る向きで、星座全体が入る大きさに寄る（カメラが天球の外に出ないよう、寄る大きさに上限を付ける）

### 4.3 テスト・検証方針

テストは過剰に広げず、変更時の不具合検出に直結する必要最低限の検証項目へ絞って実施する方針とする。検証項目は [check.yml](../.github/workflows/check.yml) の CI ワークフローと一致させる。

- **天文計算の単体テスト（`npm test` / `vitest run`）**：[vite.config.ts](../vite.config.ts) の `environment: "node"` 上でブラウザ・WebGL 非依存の純粋関数のみを対象とした以下の検証
  - J2000.0 および既知日時におけるユリウス日・GMST 計算値の一致
  - 春分・夏至・秋分・冬至における太陽視黄経（$0^\circ, 90^\circ, 180^\circ, 270^\circ$ 付近）と太陽赤緯（$0^\circ, \pm 23.44^\circ$ 付近）の算出
  - 代表都市の正午・日の出・深夜における太陽高度角・太陽方位角（東 $= 90^\circ$、南 $= 180^\circ$、西 $= 270^\circ$、南半球正午 $= 0^\circ$）・昼夜区分の判定
  - 夏至・冬至・分点における北極点の `northPoleDaylightState`（`"polar-day"` / `"polar-night"` / `"equinox-transition"`）の判定
  - 1恒星日経過時の GMST $360^\circ$ 回転と 1太陽日との約 $0.9856^\circ$（約3分56秒）差の再現
  - 月の黄緯が白道傾斜（$\pm 5.15^\circ$）の範囲に収まること、および 1恒星月での黄経復帰と 1朔望月での月相角復帰の検証
  - 満ち欠けの4点の月相角が月相ラベル（新月・上弦の月・満月・下弦の月）と一致すること、白道の黄緯が昇交点で $0^\circ$、そこから $90^\circ$ 先で傾き $5.145^\circ$ になることの検証
  - 天体衝突シミュレーターの重さ・半径が実際の値の比になっていること、実際の重さで月と木星4衛星の軌道が約2年ぶん安定すること、描いている位置と大きさで衝突を判定する（描いた絵が触れれば当たり、離れていれば当たらない）こと、全天体の描く大きさが実際の半径の順番どおりであること、投入天体どうしの吸収、同じ種類どうしの対消滅、すでに置いた天体の重力が予測に入ることと予測で実際の状態が変わらないこと、衛星を広げて描く変換が元に戻せること、母惑星（木星）が消えても変換の中心が飛ばず、予測でも実際の進行でも4衛星どうしがすぐにはぶつからないこと、母惑星が消えたあとに衛星が1つ消えても中心が動かないこと、衛星が全部消えたら中心を止め、中に生きている天体がいなくなってから変換を外すことの検証
  - リアル太陽系の表示半径が実際の半径の比を保つこと、太陽が木星より大きく水星の近日点より内側に収まることの検証（衝突判定には表示半径を使う）
  - 星座・星座の形・星座の星に解説カードがあること、距離の誤差の書き分けと、スペクトル型から星の大きさの種類を決める処理の検証
  - 実績の達成と重複達成の防止、累計（異なる5種類）の判定、リゲルを同時に5つ置く実績の判定（最大記録・ほかの天体では達成しない・シークレットの名前）、複数タブでほかのタブの記録や消去を上書きしないこと、保存データの読み込み（壊れた JSON・未知の id・型違い・リゲルの最大数がない古い保存データ・`localStorage` が使えない場合）の検証
- **TypeScript 型チェック（`npm run typecheck` / `tsc --noEmit`）**：`strict: true` 条件下での型定義とモジュール境界の整合性確認
- **ビルド確認（`npm run build` / `tsc --noEmit && vite build`）**：型チェック後の Vite 本番バンドル生成成功の確認
- **対象外とする過剰テスト**：Three.js の WebGL ピクセルスナップショットテストおよび網羅的 UI E2E 自動テストの除外（3D 表示は開発サーバー `npm run dev` での目視確認に限定）
